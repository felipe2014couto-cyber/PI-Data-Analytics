## 2. Lacunas Encontradas na Revisão

### 2.1 Alinhamento temporal — nearest-prior → exato

**Problema:** O calculador original usava estratégia "nearest prior" (buscar o limite mais recente <= timestamp da leitura). Isso permitia silenciosamente alinhar timestamps diferentes.

**Correção:** Implementada busca exata por timestamp. Se o limite não possui o mesmo timestamp da leitura, o resultado é `SEM_DADOS` para aquele limite.

### 2.2 Timestamps duplicados não rejeitados

**Problema:** O calculador original aceitava silenciosamente timestamps duplicados dentro de uma série (último vencia via dict).

**Correção:** Adicionada `_check_timestamp_consistency()` que rejeita duplicatas com `CepInputError` explícito e determinístico.

### 2.3 Mistura naive/aware não rejeitada

**Problema:** Não havia validação de consistência de timezone dentro de uma série.

**Correção:** `_check_timestamp_consistency()` agora verifica se todos os timestamps de uma série são naive ou aware. Mistura gera `CepInputError`.

### 2.4 Entrada fora de ordem

**Problema:** O calculador ordenava internamente mas não documentava o comportamento.

**Correção:** `_sort_samples()` é chamado explicitamente antes do processamento. Documentado que inputs são ordenados internamente.

### 2.5 Teste de migration real ausente

**Problema:** Os testes anteriores usavam `Base.metadata.create_all()` do conftest, não testavam upgrade/downgrade do Alembic.

**Correção:** Criados 3 testes que executam `alembic upgrade head` e `alembic downgrade` em banco temporário via subprocess.

### 2.6 Teste de rollback ausente

**Problema:** Não havia teste comprovando que falha no meio da carga provoca rollback integral.

**Correção:** Criado teste que injeta falha via monkeypatch em `upsert_cep_variables` e confirma que nenhuma alteração parcial permanece.

### 2.7 Teste de periods edge cases

**Problema:** Faltavam testes para: lista vazia, todos fora de limite, conforme quebra período, ordenação cronológica.

**Correção:** Adicionados 4 novos testes em `TestDetectOutOfLimitPeriods`.

## 3. Comportamento de Alinhamento

### Estratégia

```
Linha temporal principal: série de leitura
Para cada timestamp da leitura:
  1. Buscar EXATAMENTE o mesmo timestamp em lower, upper e target
  2. Se não existe → o valor é None → SEM_DADOS
  3. Pontos adicionais nas séries de limites são IGNORADOS
```

### Regras documentadas

- Não há interpolação temporal
- Não há busca "nearest prior"
- Timestamps extras nas séries de limites não criam novas amostras CEP
- Alvo ausente não invalida conformidade

## 10. Validação de Timezone Cross-Series (Revisão Final)

### Lacuna encontrada

O calculador original validava cada série individualmente quanto a mistura naive/aware, mas **não validava consistência entre séries**. Era possível passar leitura com timestamps aware e limites com timestamps naive sem erro.

### Correção realizada

Adicionada função `_check_cross_series_tz()` que verifica que todas as séries não-vazias compartilham a mesma categoria de timezone (naive ou aware). Chamada dentro de `calculate_compliance()` após as validações individuais.

### Comportamento

```python
# Séries mistas entre si → CepInputError explícito
# "Mistura de timestamps entre series: 'leitura' usa timestamps
#  timezone-aware, mas 'limite_inferior' usa naive."
```

### Testes adicionados (8 testes)

| Teste | Cenário |
|---|---|
| `test_reading_aware_lower_naive_raises` | leitura aware + limite inferior naive |
| `test_reading_naive_upper_aware_raises` | leitura naive + limite superior aware |
| `test_target_naive_other_aware_raises` | alvo naive + séries obrigatórias aware |
| `test_all_aware_ok` | todas aware (aceito) |
| `test_all_naive_ok` | todas naive (aceito) |
| `test_empty_target_ignored` | alvo vazio ignorado na verificação |
| `test_cross_series_error_via_calculate_compliance` | erro propaga via `calculate_compliance` |
| `test_error_message_includes_both_labels` | mensagem inclui nomes das séries |
